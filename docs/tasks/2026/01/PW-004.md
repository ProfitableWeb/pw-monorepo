### Технические требования

**1. Modal Component (переиспользуемый)**

- Portal API: `createPortal(content, document.body)`
- Focus trap: Tab/Shift+Tab циклически внутри модалки
- Keyboard: Escape для закрытия
- Click outside: клик по overlay закрывает
- Body scroll lock: блокировка скролла при открытой модалке
- Размеры: `small` (400px), `medium` (600px), `large` (900px)
- Анимации: fade in overlay + slide up content
- Accessibility: `role="dialog"`, `aria-modal="true"`

**2. Newsletter Form**

- Email валидация: `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`
- Loading state при отправке
- Success/Error сообщения
- Использует Modal компонент
- Переиспользует существующий `SocialIcons` ✅
- TODO: API integration (`/api/newsletter/subscribe`)

**3. Table of Contents (TOC)**

- Автоматическая генерация из массива `{ id, title, level }`
- Intersection Observer для highlight активной секции
- Smooth scroll: `element.scrollIntoView({ behavior: 'smooth' })`
- `position: sticky; top: 100px;`
- Desktop only (скрывается на tablet/mobile)

**4. Sidebar Widget**

- Переиспользуемый компонент для любого контента
- `position: sticky; top: 100px;`
- Переиспользует существующий `SocialIcons` ✅
- Desktop + tablet (скрывается на mobile)

**5. ArticleLayout System (универсальная система layout'ов)**

**Wrapper компонент `ArticleLayout`:**

- Принимает prop `layout: 'three-column' | 'two-column' | 'full-width'`
- Выбирает нужный layout компонент в зависимости от значения
- Используется для статей и страниц (логика как в WordPress)

**ArticleLayoutThreeColumn:**

- CSS Grid layout:
  - Desktop (>1024px): `220px | 1fr | 300px` (TOC | Content | Sidebar)
  - Tablet (768-1024px): `1fr | 280px` (Content | Sidebar)
  - Mobile (<768px): `1fr` (Content only)
- Принимает: `toc`, `sidebar`, `children`

**ArticleLayoutTwoColumn:**

- CSS Grid layout:
  - Desktop (>1024px): `1fr | 300px` (Content | Sidebar)
  - Tablet (768-1024px): `1fr | 280px` (Content | Sidebar)
  - Mobile (<768px): `1fr` (Content only)
- Принимает: `sidebar`, `children` (без TOC)

**ArticleLayoutFullWidth:**

- Контент на всю ширину экрана
- Текстовые блоки могут ограничиваться по ширине и центрироваться
- Поддержка газетной вёрстки (колонки)
- Используется для лендингов и широкого контента
- Принимает: `children` (без TOC и Sidebar)

**6. ArticleContent (рендеринг HTML)**

- Принимает HTML контент из БД
- Безопасный рендеринг HTML (санитизация при необходимости)
- Автоматическая генерация TOC из заголовков (опционально)
- Semantic HTML структура
- Поддержка всех HTML элементов (заголовки, параграфы, списки, цитаты, etc.)

**7. Контент в HTML формате**

- Контент страницы хранится в HTML формате
- В БД будет поле `content: string` (HTML)
- Моковые данные в `about-content.ts` также в HTML формате
- Структура: `<section id="..."><h2>...</h2><p>...</p></section>`

### Дизайн-система

- CSS переменные из `styles/utils/_variables.scss`
- Типографика из `styles/themes/`
- Breakpoints: mobile (<768px), tablet (768-1024px), desktop (>1024px)

- BEM-подобная структура: `.about-hero__title`, `.about-hero__subtitle`

### Риски и ограничения

- ⚠️ Дизайн в Figma может быть неполным - уточнить у дизайнера перед началом
- ⚠️ Контент в HTML формате - нужна санитизация при необходимости
- ⚠️ Автогенерация TOC из HTML - может быть сложной, рассмотреть парсинг или отдельное поле в БД
- ⚠️ Анимации могут тормозить на мобильных - использовать `prefers-reduced-motion`
- ⚠️ Intersection Observer может не работать в старых браузерах - добавить fallback
- ⚠️ Sticky может "прыгать" при скролле - проверить `top` offset с высотой AppBar
- ⚠️ Modal focus trap может конфликтовать - только одна модалка одновременно
- ⚠️ Portal может не работать на SSR - использовать `useEffect` для условного рендера
- ⚠️ Full-width layout - текстовые блоки должны ограничиваться по ширине для читаемости
