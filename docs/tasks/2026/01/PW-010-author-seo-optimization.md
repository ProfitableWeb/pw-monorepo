## 🎯 Постановка задачи

### Описание

Оптимизировать блок автора статьи под передовые практики SEO (2024-2025), добавить Schema.org разметку `Person`,
исправить использование `Organization` вместо `Person` в разметке статей, и создать страницу автора `/author` с полной
информацией.

**Контекст:** В рамках задачи PW-009 был создан блок автора статьи (`ArticleAuthorBlock`), но он не содержит Schema.org
разметки и не соответствует передовым практикам SEO для авторов контента.

### Цель

- Добавить Schema.org `Person` разметку в блок автора
- Исправить использование `Organization` на `Person` в разметке статей
- Создать страницу автора `/author` с полной информацией
- Улучшить E-E-A-T сигналы (Experience, Expertise, Authoritativeness, Trustworthiness)
- Обеспечить соответствие рекомендациям Google для авторов статей

## 📊 Текущее состояние

### ✅ Что реализовано:

1. **Семантический HTML**
   - Используется `<h3>` для имени автора
   - `<p>` для описания
   - Правильная структура с контейнерами

2. **Видимая информация**
   - Имя автора отображается
   - Описание/биография присутствует
   - Социальные сети интегрированы
   - Ссылка на профиль автора (`/author`)

3. **UX**
   - Плавные hover-эффекты
   - Адаптивный дизайн
   - Доступность

### ❌ Что отсутствует (критично для SEO):

1. **Schema.org разметка для автора**
   - Блок автора НЕ содержит JSON-LD разметку `Person`
   - Нет связи между видимым блоком и структурированными данными

2. **Неправильный тип автора в разметке статьи**
   - В `utils/seo.ts` используется `Organization` вместо `Person`

   ```typescript
   author: {
     '@type': 'Organization',  // ❌ Неправильно
     name: 'ProfitableWeb',
   }
   ```

3. **Отсутствующие поля для E-E-A-T**
   - Нет `url` автора (ссылка на профиль)
   - Нет `sameAs` (социальные сети)
   - Нет `jobTitle` (должность/роль)
   - Нет `image` (фото автора)
   - Нет `@id` (уникальный идентификатор)

4. **Отсутствие страницы автора**
   - Ссылка `/author` не ведёт на реальную страницу

## 🎯 Передовые практики SEO (2024-2025)

### Обязательные поля для `Person`:

| Поле              | Статус                  | Важность      |
| ----------------- | ----------------------- | ------------- |
| `@type: "Person"` | ❌ Отсутствует          | **Критично**  |
| `name`            | ✅ Есть (визуально)     | **Критично**  |
| `url`             | ⚠️ Частично (`/author`) | **Важно**     |
| `sameAs`          | ❌ Отсутствует          | **Важно**     |
| `jobTitle`        | ❌ Отсутствует          | Рекомендуется |
| `description`     | ✅ Есть (визуально)     | Рекомендуется |
| `image`           | ❌ Отсутствует          | Рекомендуется |
| `@id`             | ❌ Отсутствует          | Рекомендуется |

### Рекомендации Google:

1. **Использовать `Person` для индивидуальных авторов**
   - ❌ Текущее: `Organization`
   - ✅ Должно быть: `Person`

2. **Связывать автора с внешними профилями (`sameAs`)**
   - VK, Telegram, GitHub, личный сайт
   - Помогает в дезинтеграции авторов

3. **Видимая информация должна совпадать с разметкой**
   - Имя, описание, jobTitle должны совпадать

4. **Использовать стабильные идентификаторы (`@id`)**
   - Формат: `https://profitableweb.ru/author#person`
   - Помогает связать автора через разные статьи

## ⚠️ Потенциальные проблемы

1. **Несоответствие видимого контента и разметки**
   - Если в Schema.org указано одно, а на странице другое — Google может отклонить разметку
   - **Решение:** Строгое соответствие между видимым контентом и разметкой

2. **Отсутствие изображения**
   - Пока используется плейсхолдер, но для полной оптимизации нужна реальная фотография
   - **Решение:** Добавить поле `image` в конфиг, использовать плейсхолдер до готовности фото

3. **Валидация разметки**
   - Нужно проверить через Google Rich Results Test
   - **Решение:** Обязательная проверка перед коммитом
