## 🎯 Постановка задачи

### Описание

MCP-сервер (PW-061) даёт внешним AI-агентам **права на запись** в блог: создание и публикация статей, загрузка медиа,
изменение SEO. Admin API — ещё 12 роутеров с CRUD. При этом тестов у них **ноль**: 27 существующих тестов покрывают
только публичное чтение и авторизацию (`tests/test_api.py`, `tests/test_auth.py`).

PW-061-D проверял MCP вручную из Claude Code («28/28 tool calls»), но в пустой медиатеке — поэтому пропустил баг ниже.

### 🔥 Блокер: MCP-инструменты медиа обращаются к несуществующим полям

`src/mcp/tools/media.py` читает `f.original_filename`, `f.file_size`, `f.url`, `f.alt_text`. В модели `MediaFile`
(`src/models/media.py`) этих полей **нет** — есть `filename`, `size`, `storage_key`, `alt`. Нашёл mypy (PW-065).

Последствия:

- `list_media` — `AttributeError`, как только в медиатеке появится хотя бы один файл (на пустой — «работает», поэтому
  ручной тест прошёл)
- `get_media` — падает всегда
- `upload_media` — **файл загружается в хранилище и коммитится запись**, потом падает на формировании ответа; агент
  видит ошибку и, скорее всего, повторит загрузку → дубликаты
- `update_media_metadata` — `media.alt_text = ...` создаёт атрибут-пустышку на объекте, **alt не сохраняется**, а агент
  получает «успех»

Исправление: использовать реальные поля; URL строить через `storage.url(media.storage_key)`, как в
`api/admin/media.py:36`. Сначала тест, который воспроизводит, потом фикс.

### Цель

Каждый MCP-инструмент и каждый admin-эндпоинт покрыт как минимум happy-path тестом + проверкой прав. Регрессии вроде
бага выше ловятся в CI.

### Объём

**MCP — 29 инструментов** (`src/mcp/tools/`): articles 9, categories 4, tags 4, media 4, seo 3, system 3, content 2.
Плюс `resources.py`, аутентификация по API-ключу (`src/mcp/dependencies.py`), аудит (`log_mcp_action`).

**Admin API — 12 роутеров** (`src/api/admin/`): articles, categories, tags, media, users, seo, settings, storage,
system, audit_logs, errors, mcp_keys.

### Критерии приемки

**Инфраструктура**

- [ ] Фикстуры: `admin_client`, `editor_client`, `viewer_client` (залогиненные), `mcp_key` (ключ с правами)
- [ ] Фикстура хранилища на `tmp_path` (локальный storage), чтобы тесты медиа не писали в реальные uploads
- [ ] Изоляция тестов: транзакция с откатом на тест (сейчас одна SQLite-БД на сессию, состояние течёт между тестами)
- [ ] Структура: `tests/admin/test_<router>.py`, `tests/mcp/test_<tools>.py`

**MCP**

- [ ] Баг медиа: тест `upload → list → get → update alt → get` падает до фикса, проходит после
- [ ] Каждый инструмент вызывается напрямую (функция после `register`) с поддельным `ctx` — happy path
- [ ] Авторизация: без ключа / отозванный ключ / ключ viewer'а на write-инструмент → отказ
- [ ] Каждый write-инструмент пишет запись в audit log
- [ ] Один end-to-end тест по HTTP-транспорту `/mcp` (initialize → tools/list → tools/call) — ловит поломки протокола и
      lifespan
- [ ] `schedule_article` — дата в прошлом отклоняется (см. также PW-068 про автопубликацию)

**Admin API**

- [ ] Для каждого роутера: 401 без авторизации, 403 для viewer, happy path для admin
- [ ] Articles: create → update → revisions → publish → schedule → archive; slug-конфликты; M2M категорий (регрессия
      PW-054: primary-категория попадает в junction)
- [ ] Categories: нельзя удалить категорию по умолчанию; перенос статей при удалении
- [ ] Media: загрузка, ресайзы, удаление файла из хранилища
- [ ] Users: смена роли, нельзя разжаловать последнего админа (если такое правило есть — проверить, если нет — завести)
- [ ] MCP keys: создание показывает ключ один раз, в БД хранится хеш, отзыв работает

**Метрика**

- [ ] `pytest --cov=src` в CI (отчёт, без порога на первом шаге); цель следующего шага — 70% для `src/api/admin` и
      `src/mcp`

### Предложенное решение (порядок)

1. **Фикс медиа MCP с регрессионным тестом** — отдельный коммит, можно выпустить сразу.
2. Изоляция тестов + фикстуры ролей.
3. Auth-матрица (401/403) параметризованным тестом по всем admin-роутам — дёшево и закрывает самый опасный класс ошибок.
4. MCP: write-инструменты, потом read.
5. Admin: articles → media → categories → остальные.
6. Coverage в CI.
