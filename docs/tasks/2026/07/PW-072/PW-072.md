## Постановка задачи

### Описание

ProfitableWeb — живой сервис оператора ООО «Открытые Кибернетические Системы», собирающий ПДн: OAuth-регистрация
(Яндекс/Google/Telegram → email, идентификатор аккаунта, имя, аватар), комментарии, IP/сессии, Яндекс.Метрика (cookies).
По ч. 2 ст. 18.1 ФЗ-152 оператор обязан **опубликовать Политику обработки ПДн** в открытом доступе на сайте, где идёт
сбор, и обеспечить к ней неограниченный доступ; по ст. 9 — получить **согласие** субъекта (с 01.09.2025 — отдельным
действием, конкретные цели). Обязанность существует с момента сбора, независимо от подачи уведомления в РКН
(верифицировано 21.07.2026, см. `rkn-uvedomlenie-draft.md`).

### Цель

Опубликовать Политику ПДн на ProfitableWeb и оформить согласие в точках сбора (логин, комментарии).

### Критерии приёмки

- [x] Страница `/privacy` с полным текстом Политики обработки ПДн (открытый доступ, без авторизации) — **проверено в
      браузере: 14 разделов, реквизиты, контакт**
- [x] Ссылка на Политику в футере на каждой странице — **проверено (nav «Правовая информация» → /privacy)**
- [x] Уведомление о согласии в `AuthModal` (рядом с кнопками OAuth-входа), со ссылкой на Политику — **проверено в
      открытой модалке**
- [x] Уведомление о согласии в форме комментария (`ArticleCommentForm`), со ссылкой на Политику — код готов, tsc чист
      (live-тест требует API + статью)
- [x] Контент отражает реальный сбор ProfitableWeb (OAuth, комментарии, IP, Яндекс.Метрика/cookies)

### Технические решения

- **Статический роут** `apps/web/src/app/privacy/page.tsx` (не DB-страница `type=page`): юридический документ
  версионируется в git — аудит-след «какая редакция была опубликована когда». Статический сегмент перекрывает `[slug]`.
- Контент — структурированные данные в компоненте `app-privacy-page/`, отрисовка по секциям.
- Источник текста — `politika-obrabotki-pdn-draft.md` (контур ОКС), адаптирован под ProfitableWeb.

### Не входит в задачу / открытые вопросы

- **Финальная юридическая вычитка** текста Политики (Моё Дело / юрист) — драфт помечен «не юр. консультация». Публикуем
  рабочую редакцию (обязанность существует сейчас), финализация — отдельно.
- Backend-хранение факта согласия (лог согласий) — на этом этапе согласие оформляется как conclusive-action
  (вход/отправка = согласие) + информирование; журнал согласий при доработке auth.
- Подача уведомления в РКН — отдельный контур ОКС (не код).
