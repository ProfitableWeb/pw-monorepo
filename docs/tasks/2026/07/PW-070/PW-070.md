## Постановка задачи

### Описание

Деплой давно переведён с PM2 на Docker Compose (PW-043): `docker-compose.prod.yml` / `docker-compose.dev.yml` /
`docker-compose.infra.yml`, CI — `.github/workflows/deploy.yml` (master → prod) и `deploy-dev.yml` (develop → dev),
миграции Alembic выполняются в CMD `apps/api/Dockerfile` при старте контейнера. Однако PM2 / `ecosystem.config.js` всё
ещё описаны как действующий механизм в ряде живых документов, а `origin`/`gitverse` ремоуты перепутаны местами
(фактически `origin` = GitHub, деплой тянет код с него).

Сверка с реальным состоянием VM (21.07.2026): контейнеры `pw-prod-*` (:3000/:8000/:3001/:5432), `pw-dev-*`
(:3100/:8100/:3101/:5433); контур infra (Gitea) описан в `docker-compose.infra.yml`, но НЕ развёрнут (PW-043-F отложена,
контейнеров Gitea на VM нет); nginx на хосте слушает только :80; pm2 на VM не установлен; Docker без daemon.json
(json-file логи без ротации).

### Цель

Привести деплой-документацию в соответствие с Docker-реальностью, убрать PM2 как «действующий» механизм, решить судьбу
`ecosystem.config.js`.
